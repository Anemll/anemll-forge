# Evidence for the tree-verification claims

Reviewed 22 November 2026 against manuscript revision `9c3da09`. The comparison covers the six contribution statements and the M6 findings. Hardware evidence comes from archived runs and the implementation. No new device benchmark was run for this review.

## Closest prior art

| Forge claim | What the primary source establishes | What the M6 work demonstrates |
|---|---|---|
| 1. One tree in eight rows | DDTree constructs a bounded tree from one parallel draft and uses a tree mask. LumoTree pads trees for reusable execution shapes. TensorFold documents measured-cost row allocation on Metal for the same model family. [DDTree §§4, 5.3](https://arxiv.org/pdf/2604.12989v1) · [LumoTree §III](https://arxiv.org/html/2609.23900v3) · [TensorFold v1.3.2 recipe](https://github.com/ashhart/TensorFold/blob/v1.3.2/docs/recipes/qwen3.8-27b.md) | The chain and tree share weights and a physical eight-row budget. A fork triggers the separate tree entry. The identical row budget still permits different latency. |
| 2. Short convolution | MFD Appendix C, immediately after Lemma 2, specifies nearest ancestors plus pre-root convolution history. It also reports finite-precision differences from native execution. TreeWY §3, equations 2–3, establishes the strict-ancestor GDN solve. [Multi-Future Drafting](https://arxiv.org/html/2611.13017v1) · [TreeWY](https://arxiv.org/html/2608.20961v2) | The ANE-specific implementation retains the original convolution. A chain tap map minus the constant chain shift is zero, so the correction vanishes on that control. The tested ANE one-hot matmul introduced rounding. The reviewed papers describe different formulations. A literature comparison cannot establish priority over all implementations. |
| 3. Commit | TreeWY eq. 3 reconstructs one selected state from factors. MFD Appendix C computes the accepted update without replay. LumoTree Algorithm 1 lines 9–15 replays rounded recurrent operands, gathers convolution history, remaps KV and selects the hidden row for drafting. SpecLA §5.2 also delays state updates. [TreeWY](https://arxiv.org/html/2608.20961v2) · [MFD](https://arxiv.org/html/2611.13017v1) · [LumoTree](https://arxiv.org/html/2609.23900v3) · [SpecLA](https://arxiv.org/html/2607.16673v1) | Forge compacts the pending k/u/wk and decay rows, convolution rows and new KV, including scales on the split path. It gathers the accepted drafter features separately and calls the existing chain accept routine. No full recurrent matrix moves from row to row. |
| 4. Split target | Mirror-SD maps model-level drafting to NPUs and verification to GPUs. Its experimental setup identifies eight M2 Ultra systems. [Mirror-SD §3.3 and experimental setup](https://arxiv.org/html/2510.13161v2) | On one M6 the 96K entry sandwiches two GPU attention calls between ANE target functions per package. The GPU writes directly to shared cache storage. Later off-prefix compaction can still move KV. The split functions are independent of key width. The 128K kernel probe and a served 128K model are different evidence. |
| 5. Static slices | AWS Neuron documents selecting the smallest compiled decode context bucket that covers the KV span, including room for speculative tokens. [AWS design](https://awsdocs-neuron.readthedocs-hosted.com/en/v2.33.1/vllm-neuron/docs/design/vllm/decode-context-length-bucketing.html) | Four intermediate Forge widths reuse existing whole KV segments. The guard covers all eight new rows. The logits and throughput comparisons use the resident larger entry as the baseline. |
| 6. Wider-row cost | Sequoia §4.1 profiles target latency by tree size. DDTree §5.3 finds throughput peaks near budgets 256–512 on one GPU evaluation and declines at 1024. HybridSpec reports 71% longer verification at length 16 than at 4 for its DFlash hybrid configuration. [Sequoia](https://arxiv.org/pdf/2402.12374v3) · [DDTree](https://arxiv.org/pdf/2604.12989v1) · [HybridSpec](https://arxiv.org/html/2611.04055v1) | The contribution is the per-operator breakdown and adjacent-width measurements for this ANE. The older 8/16/32 study and the improved 8–16 sweep use different programs and denominators. Only the group latency is directly measured in the sweep. |

**Other primary checks.** Weaver builds a conditional tree from a factorized drafter and derives rollback-free GDN verification. Twig stores speculative state as token factors and reconstructs the accepted state. STree treats structured state-space models and their attention hybrids. HybridSpec studies the length of a speculative chain on GDN-MoE targets. Attributing one common tree algorithm to all four obscures these differences. [Weaver v3](https://arxiv.org/abs/2607.06763v3) · [Twig v2](https://arxiv.org/abs/2608.01651v2) · [STree, NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/a7efd7734bb2e79997f8d1137ece3f09-Abstract-Conference.html) · [HybridSpec](https://arxiv.org/html/2611.04055v1)

## M6 evidence ledger

Dated paths below are relative to `research/v8_prefill/results/` on M6. Working-code paths are relative to the recorded V8 working tree. Each row identifies the experiment needed to interpret the number.

| Finding | Archived evidence and interpretation |
|---|---|
| Shared bandwidth | `17nov/README.md` bandwidth suite, `18nov/README.md` GPU/ANE coupling, and `pipe/unit/DECODE_GPU_ATTENTION.md` bandwidth section. 156 and 121 GB/s separately, 87 + 77 GB/s concurrently. The tested compute and streaming mixes behaved differently. |
| Drafter placement | `19nov/README.md` §5, GPU cost twin and overlap table. Synthetic indices and 16 physical rows. In the back-to-back 32K arm verify rose from 121.3 to 151.3 ms. The 8.9 ms standalone result omits the complete served path. `21nov/README.md` draft phase profile gives 12.3 ms ANE and about 1 ms host. |
| Clock hold | `18nov/README.md`, GPU clock section, and `18nov/gpu_clock/README.md`. Four server pairs at 66–70K: 138.2 → 122.4 ms verify, 152.5 → 137 ms cycle, +2.1 W. The separate integrated hold test reports 136.1 → 119.1 ms and +2.66 W. The two figures use different runs. |
| Ordering and latency | `pipe/unit/DECODE_GPU_ATTENTION.md`, Core AI ComputeStream tests and latency breakdown. About 0.65 ms per serial GPU round trip above kernel time. `21nov/README.md` handoff probe logged two 100 s stalls and no valid median for the proposed drafter join. |
| Same-function concurrency | `19nov/README.md`, G256 quad prefill experiment. Concurrent launches of the same ffn2_L corrupted output. A lock restored parity. The served staggered schedule passed its checks. |
| Binding limits | `20nov/README.md` D2 four-block 32K compile failure near 51 bindings. `22nov/README.md` item 1, step A gives 42 bound tensors for both the 24K slice and 32K entry, 46 for the 48K slice and 64K entry. The observation applies to that compiler and buffer interface. |
| Exactness | `20nov/README.md` A2, A8 and D4. D4 supersedes A8's first attribution: pending differences traced to gathered keys, with cumulative decay identical in that probe. D4 form comparison 12/12 outputs, full package-0 g0/g1 checks 12/12 and 13/13, forced-chain greedy replies 45/45. Branched logits and next-state parity on arbitrary paths remain open. |
| Width | `20nov/README.md` A2, A5–A6 and T3, then `21nov/YOLO_REPORT.md` §4 and `21nov/widths/widths_summary.json`. Old three-mixer result +27/+130% at 16/32. New 32K four-layer branched probe 6.750/7.089/7.096 ms at 14/15/16, largest block spread 0.068 ms. Wider greedy throughput uses fixed anchors and measured group costs. |
| JetSpec++ | `20nov/README.md` D2, E1–E3 and `20nov/e3/projection_ANE_split.json`. 22.2 ms per serial 16-row adapter pass at 8K. Projected throughput deficit was 12–23% at 8K for J0-R0 and 43–46% at 32K for J3-R3. Head and verify costs, number of passes and oracle replay enter the estimate. |
| Repeatability and comparisons | `20nov/bench/{chain_v1,chain_v2_ctl}.json`, `21nov/YOLO_REPORT.md` §2 and `22nov/README.md` sliced block 2. Same-output restart pair differed 4.4%. Sampled tree blocks used new seeds in the opposite order. The slicing ABBA has 152 matched replies, +3.40% all sets, +2.49% excluding seed 7100. The two speedups used different baselines. |

**Serving details added from the review.** `21nov/YOLO_REPORT.md` §1 records the split plan/mask ordering fix and its CPU tests. `22nov_review/tree_audit.json` covers all 5,040 topological parent arrays for eight rows and the increasing-path compaction tests on CPU. `21nov/README.md` leftover KV experiment records 1/9 vs 9/9 fresh-matching replies after a controlled long request. These are distinct failure modes from proposal quality. `pipe/tree_verify.py` methods `compact` and `cycle` distinguish the in-buffer moves, feature gather and ordinary chain accept.
